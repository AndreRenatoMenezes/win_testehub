1. Visao Geral

O Hardware Test Hub e um framework Windows para validacao de hardware que automatiza a preparacao do ambiente, execucao de testes de diagnostico (CPU, memoria, disco, rede, boot/shutdown) e geracao de relatorios. Atraves de um menu interativo no console, o operador seleciona quais testes executar e acompanha o progresso em tempo real. Os resultados sao persistidos em multiplos formatos (HTML, CSV, JSON) com rastreabilidade completa por cenario.

2. Pre-requisitos

2.1 Hardware e Sistema Operacional

RequisitoEspecificacao
Sistema OperacionalWindows 10 ou Windows 11
PrivilegiosAcesso de Administrador local
Conexao de redeNecessaria para testes de rede e instalacao de dependencias
Espaco em discoMinimo 10 GB livres (teste de disco cria arquivo temporario de 8 GB)

2.2 Software

Os itens abaixo sao instalados automaticamente pela Fase de Setup do hub. Nao e necessario instala-los manualmente antes da primeira execucao:

  • Python 3.x (com ambiente virtual .venv)
  • Google Chrome (para teste de rede)
  • Dependencias Python: psutil, speedtest-cli, requests, selenium, pandas, pyautogui, pyperclip, pynput

2.3 Rede Tecnico

O teste de rede acessa o servidor de speedtest interno, cuja URL fica fora do repositorio: chave SpeedtestUrl do config.local.json na raiz do hub (modelo em config.local.example.json) ou variavel de ambiente HUB_SPEEDTEST_URL. Verifique se a maquina tem acesso a essa URL antes de executar o modulo de rede.

2.4 Estrutura de Pastas Esperada Tecnico

C:\TesteHub\
  hub.bat              # Ponto de entrada
  hub.ps1              # Orquestrador principal
  config.json          # Configuracoes
  Setup\environment\   # Scripts de setup (9 scripts)
  Testes\              # Modulos de teste (4 categorias)
  Logs\                # Resultados por execucao
  Traces\              # Evidencias por cenario
Importante O hub espera estar em C:\TesteHub. Caso utilize outro caminho, ajuste a referencia no hub.bat.

Ao iniciar, o hub exibe os ultimos 5 cenarios existentes (se houver) e oferece duas opcoes:

O nome do cenario e combinado com o hostname e a data, resultando em algo como: ImagemLimpa_DESKTOP-ABC_2026-04-15

5. Cenarios e Re-execucao

5.1 O que e um Cenario

Um cenario e uma sessao de testes associada a uma maquina e data. Ele agrupa todas as execucoes (runs) e suas evidencias em uma unica pasta dentro de Traces/. Isso permite:

  • Executar testes em diferentes momentos (dias) e consolidar resultados
  • Re-executar apenas os testes que falharam
  • Manter historico completo de todas as tentativas

5.2 Continuar um Cenario Existente

Ao iniciar o hub, selecione o numero do cenario que deseja continuar. O menu de testes mostrara o status da ultima execucao de cada teste, permitindo selecionar apenas os pendentes ou falhos.

5.3 Re-execucao de Testes

Ao re-executar um teste que ja foi rodado anteriormente:

  1. As evidencias da execucao anterior sao automaticamente movidas para a pasta _anterior/
  2. O teste roda novamente e gera novas evidencias
  3. O _state.json e atualizado com a nova run
Nenhuma evidencia e perdida O historico completo fica preservado em _anterior/.

5.4 Estrutura de um Cenario Tecnico

Traces/
  ImagemLimpa_DESKTOP-ABC_2026-04-15/
    _state.json              # Estado e historico de todas as runs
    _relatorio.html          # Relatorio consolidado
    _relatorio.csv
    _relatorio.json
    1_cpu_memo/              # Evidencias atuais do teste de CPU
    2_disco/                 # Evidencias atuais do teste de disco
    3_rede/                  # Evidencias atuais do teste de rede
    4_boot_shutdown/         # Evidencias atuais do teste de boot
    _anterior/               # Evidencias de execucoes anteriores
      run1_2026-04-15 09-30-00/
      run2_2026-04-15 14-00-00/

6.3 Interpretar o Relatorio HTML

O relatorio HTML (_relatorio.html) contem:

  • Cabecalho: Nome do cenario, maquina, data, estatisticas gerais
  • Tabela de resultados: Cada teste com status colorido, duracao, evidencias
  • Detalhes de erro: Para testes FAIL, as ultimas linhas de erro sao exibidas

7. Troubleshooting

7.1 Erros Comuns

ProblemaCausa provavelSolucao
Hub nao inicia / fecha imediatamente Falta de privilegio de admin Execute hub.bat como Administrador (clique direito → Executar como administrador)
"Python nao encontrado" Python nao instalado ou .venv ausente Re-execute o setup selecionando scripts 4 e 5
Teste de rede falha com "Chrome nao encontrado" Google Chrome nao instalado Re-execute o setup selecionando script 7
Teste de disco falha rapidamente Espaco insuficiente em disco Libere pelo menos 10 GB no disco principal
Overlay visual nao aparece Problema com tkinter Verifique se o Python tem suporte a tkinter (padrao na instalacao oficial)
Teste de boot/shutdown nao completa Task Scheduler falhou Verifique se a tarefa BootShutdownTest existe no Agendador de Tarefas

7.2 Re-executar um Setup Individual

Se um setup especifico falhou, nao e necessario re-executar todos:

  1. Abra hub.bat
  2. Na Fase de Setup, marque apenas o script que precisa ser re-executado
  3. Confirme com Enter

7.3 Variaveis de Ambiente e config.json Tecnico

O hub injeta as seguintes variaveis de ambiente para cada teste:

VariavelDescricao
HUB_EVIDENCE_DIRPasta onde o teste deve salvar suas evidencias
HUB_TRACE_DIRIgual a HUB_EVIDENCE_DIR
HUB_TRACE_ROOTPasta raiz do cenario atual

Configuracoes em config.json:

{
    "SkipSetup": false,
    "Paths": {
        "SetupRoot": "Setup",
        "TestsRoot": "Testes",
        "LogDir": "Logs",
        "ResultsDir": "Logs",
        "TracesDir": "Traces"
    },
    "Settings": {
        "PythonVenvName": ".venv",
        "HtmlReportTitle": "Hardware Test Hub - Relatorio Final"
    }
}
